# 三维模型文件上限调整设计

## 目标

将所有三维模型文件入口的大小上限从 128 MiB 统一提高到 512 MiB，同时保持 G-code 文件的 1 GiB 上限不变。

## 范围

- 主模型支持的 GLB、OBJ、PLY、PCD 文件上限为 512 MiB。
- 参考模型支持的 PLY、PCD、GLB 文件上限为 512 MiB。
- 文件选择、拖放、原文件重载和主进程读取采用相同上限。
- 更新界面错误提示和 README 中的限制说明。

不改变支持的文件格式、模型解析方式、G-code 上限或渲染复杂度保护策略。

## 实现设计

继续以 `src/shared/files.ts` 中的 `maxFileBytes` 作为三维模型上限的唯一来源，将其值改为 `512 * 1024 * 1024`。渲染进程和主进程均复用该常量，避免不同入口出现不一致的限制。

所有写死的 `128 MiB` 提示改为 `512 MiB`。主进程的打开文件校验按扩展名区分 G-code 和三维模型，使其与渲染进程及重载路径一致。

## 错误处理

空文件、不支持的格式和超过上限的文件继续在读取或解析前拒绝。错误信息明确显示 G-code 为 1 GiB、三维模型为 512 MiB；参考模型提示显示 512 MiB。

## 验证

- 为共享大小常量及边界行为补充测试：512 MiB 允许，超过 512 MiB 拒绝，G-code 仍使用 1 GiB。
- 运行类型检查和现有测试，确认所有入口引用一致。
- 搜索并清除面向用户文案中遗留的 `128 MiB` 限制说明。

## 风险

三维模型仍会整文件读入内存，解析和 GPU 数据可能占用文件大小数倍的内存。512 MiB 是容量与稳定性的折中，不保证所有达到上限的复杂模型都能在低内存设备上顺畅加载；解析失败仍通过现有错误处理反馈。
